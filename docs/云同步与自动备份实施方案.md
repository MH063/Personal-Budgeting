# 云同步与自动备份实施方案（仅方案，不实现）

> 本文档仅为技术实施方案，不含代码实现。供后续排期评估使用。

## 背景

当前 moneybook 为纯本地存储：
- 浏览器模式：sql.js 数据库以 base64 存于 `localStorage`（key: `moneybook.sqljs.v2`）
- Tauri 桌面模式：SQLite 文件 `moneybook.db`（含 `-wal`/`-shm`）
- 数据完全存储在本机，无多端同步、无自动备份

## 一、云同步方案

### 1.1 选型对比

| 方案 | 优点 | 缺点 | 适合 |
| --- | --- | --- | --- |
| **自建服务器 + 版本化 API** | 可控、可加密、可演进 | 需维护服务器与账号体系 | 长期产品化 |
| **对象存储（S3/OSS/WebDAV）直接同步文件** | 实现简单、免账号体系 | 无冲突合并，整库覆盖风险 | 单人单机保守 |
| **Git 私有仓库** | 天然版本历史、冲突可回滚 | 数据二进制快照大、需 Git 环境 | 开发者自用 |
| **厂商网盘（WebDAV 类）** | 用户已有账号、成本低 | 无行级合并、隐私风险 | 个人轻量 |

**推荐：自建服务器 + 版本号增量同步**（若仅个人使用且不想运维，退而求其次选 WebDAV + 整库导出导入）。

### 1.2 数据模型

- 每个账本对应一个同步数据集，维护 `sync_version`（单调递增整数）。
- 服务器表：
  - `sync_meta(user/device_id, ledger_id, head_version, updated_at)`
  - `sync_ops(seq INTEGER PRIMARY KEY, ledger_id, version, entity, entity_id, op, payload_json, ts)`
- 客户端本地表：
  - `sync_state(device_id, ledger_id, pulled_version, pushed_version)`

### 1.3 同步流程（双向）

1. **拉取**：客户端携带 `pulled_version` 请求 `GET /sync?since={v}`，服务器返回 `(v, pulled_version]` 区间的操作日志，客户端按序重放，更新 `pulled_version`。
2. **推送**：客户端本地写操作通过 `recordToTrash` 同款"操作日志表"记录（可复用改造 trash 快照机制），批量上送 `POST /sync`（带 `pushed_version`），服务器校验无冲突后追加 ops 并返回新 `head_version`。
3. **冲突**：采用**版本号+行级 last-write-wins（LWW）**策略：
   - 同实体同字段冲突时按 `op.ts` 时间戳取新；
   - 特殊实体（如预算月度 UPSERT、账户余额）用「操作语义」合并而非覆盖（保留双方差异并提示）。
4. **幂等**：每条 op 携带客户端生成的 `op_id`（UUID），服务器去重，保证断线重传安全。

### 1.4 双后端桥接

- 复用 `db.ts` 的 `exportDb()` / `importDb()` 与 Tauri 端备份命令作为兜底"手动一键同步"入口。
- 目标：为两套存储（sql.js / SQLite）提供统一的操作日志源，同步层只感知 op，不感知存储后端。

### 1.5 加密与隐私

- **端到端加密**：同步数据采用用户口令派生密钥（PBKDF2/scrypt）加密后再上送；服务器只存密文。
- 凭证（AI API Key）**绝不入同步数据**（现有 `useAIStore` 已加密储存且含有独立密钥）。
- 明细脱敏：若必须明文传输，先经 `maskSensitive/sanitizeRow`（`src/lib/sanitize.ts`）脱敏。

## 二、自动备份方案

### 2.1 触发策略

| 模式 | 触发 | 说明 |
| --- | --- | --- |
| 浏览器模式 | 启动时 + 每日定时（页面可见时用 `setInterval` 检测） | localStorage 有 5MB 配额压力，备份频率宜 1 次/天 |
| Tauri 桌面模式 | 应用启动时 + 退出前 + 可配置每日 | 复用 `Commands::backup` 的 `backup_database` |

### 2.2 备份内容与轮转

- 备份 = `exportDb()` 生成的 base64 + 元信息（时间戳、账本数、schema 版本）。
- 存储位置：浏览器 → 触发下载 `.moneybook-backup-YYYY-MM-DD.b64`；桌面 → 用户数据目录 `backups/`。
- **轮转策略**：保留最近 7 份每日 + 最近 12 份每周，超出自动清理（`cleanOldBackups`）。
- 提供「恢复演练」入口：设置页导入备份并在临时账本中验证可读。

### 2.3 恢复流程

- 复用现有 `BackupRestore.tsx` 的导入路径（`importDb`）。
- 恢复前**自动创建当前数据快照**（防止误覆盖），确认后再导入。

## 三、风险与建议

1. **localStorage 配额**：5MB 上限远小于 SQLite；云同步前应提示并支持"仅 Tauri 端开启云同步"。
2. **加密密钥管理**：口令丢失将无法解密，须提供「导出恢复密钥」提示。
3. **分阶段落地建议**：先做「自动备份」（价值高、风险低），再做「云同步」（需服务器，周期较长）。
